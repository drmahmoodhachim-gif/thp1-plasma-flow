How the codes work

Every script used to read the cytometer files, draw the figures, and build this live page. Click a file name to open it on GitHub. Plain-language notes sit under each step.

1. Run everything (one command)

Put the 10 .fcs tubes and the FlowJo .wsp file in one folder. Then, from a terminal:

pip install -r flow_analysis/requirements.txt
cd flow_analysis
python run_all.py --data "../Flow Files" --out ../output --skip-overview

That one script calls the others in order: check FlowJo gates → figures 1–9 → tables → fancy figures 10–16 → 3D HTML. About one minute.

To rebuild only the live website data after that:

python flow_analysis/export_web_data.py --data "Flow Files" --out site/data

Open run_all.py Open requirements.txt Open METHODS.md

2. What each script does

Start at the top and work down. You only need to edit config.py if a gate or file name changes.

Settings

config.py — File names, original FlowJo polygons, recommended gates, dye cut-off (535), singlet ratio (0.55–0.90), colours. Change a gate here only.

plotstyle.py — Shared look of the PNG figures (fonts, axes, save at 300 dpi).

Read the cytometer files

flowdata.py — Opens each .fcs file, applies the original and recommended gates, logicle (biexponential) dye scale, and 95% confidence intervals.

parse_workspace.py — Reads gates from the FlowJo workspace and checks that Python counts match FlowJo (within about 1.5%).

Figures and tables

figures_overview.py — Exploratory grids of every tube through the original gates (fig S0). Slow; skip with --skip-overview.

figures_part1.py — Figures 1–5: original gating and why it over-estimates viability.

figures_part2.py — Figures 6–9 and S1: recommended gating, dose–response, composition, granularity.

figures_fancy.py — Figures 10–16 (summary, ridgeline, density, funnel, joint plot, donuts, debris) and the original 3D HTML explorer.

tables.py — Four CSV tables: original gating, event rates, recommended viability with CIs, dose-trend test.

extras/make_deck.js — Optional: rebuilds the PowerPoint from the PNGs (needs Node.js and pptxgenjs).

Live website

export_web_data.py — Packs all ~560,000 events into site/data/events.bin plus meta.json so the browser can re-gate without Python.

interactive_dashboard.py — Earlier local HTML dashboard (sampled 3D view). The public site below replaced this.

site/index.html — Page layout: gate sliders, tube tabs, figure tabs.

site/app.js — Applies your gates in the browser and redraws every figure.

site/styles.css — Colours and layout.

site/config.js — Supabase address so saved gate presets can be stored and loaded.

netlify.toml — Tells Netlify to publish the site/ folder.

4. How the live interactive page is built

  1. Python reads the .fcs files (flowdata.py).
  2. export_web_data.py writes site/data/events.bin (raw FSC, SSC, FSC-H, dye for every event) and site/data/meta.json (gate polygons, tube names).
  3. The browser loads those files. app.js tests each event against the sliders you set (dye cut-off, singlet band, cell-size gate, or original FlowJo polygons).
  4. Every figure tab is redrawn from that new classification. Nothing is a static PNG on this page.
  5. If you save a preset, config.js sends it to the Supabase table e1_flow_gate_presets.
  6. Netlify hosts the site/ folder, as set in netlify.toml.
